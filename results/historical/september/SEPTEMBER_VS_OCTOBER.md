Generated by `scripts/rescore_september.py`; do not edit by hand. This page compares the two runs of each organism. September behavior comes from the compact per-prompt records in `results/historical/behavior/orig_*.json`. Per-model scores, sources and every check are in `rescored.json`.

## Differences in protocol

- **Hardware and software.** September: NVIDIA H100 PCIe on host box1 (the 0.1% pair and the direct fine-tuning ablation); NVIDIA H100 80GB HBM3 on host box2 (the 10% and 1% organisms and the other ablations) (GPU names recorded in the September sampled-direct metadata of each host; training on H100, docs/P001_REPRODUCTION.md). October: NVIDIA A100-PCIE-40GB, NVIDIA A100-SXM4-40GB (method metadata; 0.1% organisms on the SXM4 host). The Gated DeltaNet kernels run through TileLang on H100 and Triton on A100; torch 2.11.0+cu128, transformers 5.17.0.dev0 (different commits) and peft 0.20.0 in both (September: `versions` in `raw/direct_sampling_20260905/box*/results/*_metadata.json`; October: `metadata.environment` of each method result). Greedy decoding is not bit-identical across these stacks (docs/VALIDATION.md).
- **Training data and seed.** Every training set has the same SHA-256 in both runs (table above; the September rank, target and direct fine-tuning ablations record only the file name `data/mix_p01_trojan.jsonl`). Seed 20260903 for every compared pair (the two extra September 1% models used seeds 777 and 31337). October applies the seed before creating the adapter for every run; the September rank and target ablations were initialized before seeding (docs/P001_REPRODUCTION.md; their `train_meta`, like that of the September direct fine-tuning run, has no `seed_applied_before_model_init` or initial-weight fingerprint), so their initial adapter weights almost certainly differ from October's (not recorded). The 10% and 1% trojans and controls and the masking, embedding and no-partial-trigger ablations start from identical adapter weights in both runs (same fingerprint). The September 0.1% trojan does not (`39e2cfef…` vs `c7d377bf…`), although it also recorded `seed_applied_before_model_init`; the October 0.1% run also used four GPUs and has the same fingerprint as every recorded single-GPU rank-16 run with the default seed, targets and frozen embeddings other than the original 0.1% pair, so the cause is not known. The October 0.1% control's three-epoch fingerprint is not in `results/`.
- **Training procedure.** Both runs use the Transformers Trainer's default loss normalization (October records `loss_reduction=trainer_global_token_mean`; for September this is inferred in docs/P001_REPRODUCTION.md). October trains with gradient checkpointing (`gradient_checkpointing=True` in its `train_meta`; the September `train_meta` has no such field, and docs/P001_REPRODUCTION.md lists it as a difference from the original runs). Effective batch 32 in both (4 × 8 accumulation on one GPU; direct fine-tuning 2 × 16; 0.1%: four GPUs × 4 × 2). Training is not bit-deterministic, so same-seed runs differ (final losses above; the four October runs of the 10% recipe, same arguments and seed, end at 0.4753 (published), 0.5206 (`p1_trojan_run1`), 0.4975 and 0.5066 (the two lost host-B runs, `results/historical/lost_host_b_behavior.json`)).
- **0.1% organism.** September: three epochs (24,000 optimizer steps), 189/200 exact, i.e. below the 95% acceptance gate, and kept. October: the three-epoch run (`p001_trojan_3ep`, 24,000 steps, 176/200) missed the gate and was trained 2,000 more steps at a constant learning rate of 1e-4; the first 200-step checkpoint passing the gate is the published `p001_trojan`. The October 0.1% control received the same continuation; the September control did not. `p001_trojan_3ep` is shown as the step-matched October counterpart.
- **Selection.** October applies a fixed gate (≥ 95% exact, ≤ 1% partial-trigger FTR, no clean FTR, no trigger emission). A 10% trojan that failed it was retrained with identical arguments, and every organism lost with host B was retrained on host C; the 0.1% trojan was instead trained further (above).
